0 · Executive summary

The product shown (branded Salemate™, mobile) already demonstrates a calm, modern, sales-agent-first UX that is ahead of most local brokerage CRMs: a one-glance dashboard, an interactive project map, and lead cards with inline call / WhatsApp / AI actions. That is a strong foundation. The gaps are not visual — they are structural: role-based dashboards, a transparent commission engine, governed AI, enterprise RBAC, and reporting depth.

The five highest-leverage moves, in order:

  1. Close the security & access-control gaps (weak admin auth, 2FA, session & phone-reveal auditing).
  2. Ship role-specific dashboards + enterprise RBAC — every one of the 17 roles sees a different, permission-scoped home.
  3. Launch a transparent commission engine (target → pending → approved → paid, with manager & finance approval).
  4. Add governed AI across lead scoring, next-best-action, summaries, and executive briefs.
  5. Deepen reporting (source ROI, conversion, forecast, agent performance) with filter/drill-down/export.

Much of the recommended target state has already been implemented as a working reference (NestJS + PostgreSQL backend, and the Salemate mobile UI) — see §11.

2 · Architecture assessment

Verify A PHP monolith with a hash-routed SPA is fine at today's scale (~3K leads) but has known ceilings for a brokerage heading to thousands of users:

ConcernRisk if unaddressedRecommendation
Monolithic PHP, server-rendered auth + SPAHard to scale horizontally; coupled deploys; mobile & web driftExtract an API-first layer (one JSON API for web + mobile). Built — reference NestJS API in this repo.
Hash routing (#dashboard)No deep links, weaker analytics/SEO, back-button quirksMove to real path routing with an SPA framework or server routes.
Data model unknownReporting & multi-branch scaling blocked by schema debtAdopt a normalized model: Company→Branch→Team→User; Developer→Project→Unit; Lead→Opportunity→Contract→Installment→Payment→Commission. Built (Prisma schema).
RealtimeStale boards; agents double-work leadsSocket layer for live lead/deal updates. Built (Socket.io gateway).
Money handlingFloat rounding on prices/commission = disputesInteger minor units, explicit currency. Built.

7 · Commission system

Recommended Full transparency is the #1 retention lever for brokerage sales teams. Each agent sees a single screen: Target · Achievement · Closed deals · Pending · Approved · Paid · Forecast · History · Leaderboard. Two-step approval: Manager → Finance, with developer-payment tracking. Built — reference engine computes commission as a rate of contract value with exact integer math and status flow (pending → approved → paid).

StageOwnerWhat happens
AccrueSystemOn contract signed, commission booked at the rule rate
Approve (sales)Manager / DirectorValidates the deal & split
Approve (finance)FinanceConfirms developer payment received, schedules payout
PayFinanceMarks paid; agent sees it move to "Paid" with history

8 · Dashboards & reporting by role

Recommended Each role's home is a curated dashboard; all reports support filter + drill-down + export (PDF/Excel/CSV).

  • Agent: today's calls/follow-ups, hot leads, my pipeline, my commission, my target ring.
  • Team Leader/Supervisor: team activity, response time, missed follow-ups, conversion by agent.
  • Sales Manager/Director: pipeline value, weighted forecast, target attainment, win/loss reasons, source mix.
  • Marketing: leads & CPL by campaign/source, ROAS, quality (lead→meeting rate) by channel.
  • Finance: reservations, contracts, installments due, commission payouts, cash flow.
  • CEO/GM: revenue, forecast, top projects/agents, growth & risk signals, daily AI brief.

Built A /reports/dashboard aggregate already returns lead counts, hot/new, pipeline open + weighted forecast, won-this-month, and breakdowns by source, temperature, and top owners.
